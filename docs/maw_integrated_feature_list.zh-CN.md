# maw 两组需求合并后的目标功能清单

日期：2026-10-23。用途：定义综合完成后用户可以使用的功能；这是一份目标范围清单，不表示下列能力已经全部实现，也不是开发任务拆分。

需求来源：

- A：五张 AI 会话协作截图，提供总览、工程统计、全天热图、小时执行时间轴、会话轮次与用量明细。
- B：“一个调度中枢＋工具接入器”方案，提供节点管理、任务派发、状态汇聚、工作目录和结果验收需求。
- 基线：现有 maw 的蓝图、任务依赖、工作者身份、持久 worktree、提交／评审／合入、跨工程看板和本机中枢。

产品定位：**本机多工具 Agent 任务与执行中枢**。统一创建和分配任务，收取交付与验证证据，并通过时间轴解释执行过程和资源投入。

以下“保留”表示已有实现基础；“扩展”表示已有路径需补齐；“新增”表示新功能。它们不是上线验收状态。判断依据见 [发展分析](maw_iteration_analysis.md) 和 [CLI 实测](CLI_SMOKE_TEST.zh-CN.md)。

## 10. 工程与工具统计

| 编号 | 完成后的功能 | 当前基础 |
| --- | --- | --- |
| F39 | 查看各工程任务与执行批次数、已验收／已合入成果、阻塞和失败重试情况 | 扩展现有快照统计与事件 |
| F40 | 展示已观测执行时长累计、活跃时间覆盖和按小时的分布，并与任务阶段驻留分开 | 新增 |
| F41 | 对比工具来源的任务量、执行量与已知消耗，明确每张图的单位和覆盖范围 | 新增 |
| F42 | 查看已知输入／输出／缓存 Token、缺失情况与采集覆盖率，下钻到执行批次或轮次 | 新增；按来源能力启用 |
| F43 | 展示活跃期间平均并发及同一口径下的工程／日期比较；定位长时间停留、反复失败和依赖积压 | 新增 |

统计必须满足：

- 执行累计是各已观测执行区间之和；活跃覆盖是区间并集，两者不能混用。
- 活跃期间平均并发为累计执行时长除以执行区间并集时长；无可用区间或分母为 0 时不生成该值。
- 无事件不自动归为人工等待；未知 Token 不是 0。来源只有进度事件时展示事件活跃度，不冒充执行覆盖。
- 阶段驻留可帮助发现延迟，但不等于该阶段内一直有模型或人在工作。
- 汇总可追溯到明细，不以高工时、高 Token 或高并发作为生产力评分，不直接推算节省人力倍数。

## 页面与操作入口

建议在现有工作台内组织以下入口，避免为每款工具另建一套页面：

| 入口 | 用户主要完成什么 |
| --- | --- |
| 总览 | 跨工程查看任务进度、节点容量、异常和当日交付 |
| 工程 | 查看该工程的任务、执行历史、统计及结果 |
| 任务 | 创建／导入任务，看板与拓扑切换，领取／派发，查看依赖与验收 |
| 节点 | 接入工具、检查就绪情况、设置容量和接收任务模式 |
| 执行详情 | 观察本次运行、处理等待／失败、取消、查看结果与历史重试 |
| 时间轴 | 全天 → 小时 → 执行批次 → 可用的会话／轮次下钻 |
| 结果与复盘 | 汇总已验收产物与验证证据，定位阻塞、返工及交付延迟 |
| 设置 | 接入、执行策略、采集、通知及界面偏好 |

这些是信息入口，可以使用页面、标签或抽屉实现，不要求八个独立顶级页面。执行与验收操作需要新增对应服务端入口，不能只加按钮。

## 综合完成的验收场景

1. 用户在一个工程建立带输入、依赖、读写范围和验收方式的任务；系统说明哪些题可开始。
2. 用户指定已就绪的 CLI 节点，或允许自动选择；中枢准确绑定所选任务及执行槽，准备对应目录。
3. 接入器开始执行；工作台实时显示运行状态，等待授权时明确提示，其他无冲突任务可继续。
4. 运行结束后，中枢收取产物和验证结果；代码任务按策略评审与合入，非代码任务按其验收方式确认。
5. 用户从工程总览进入小时视图和执行详情，能解释时间、失败重试和已知用量，并打开真实交付证据。
6. 人工接入客户端可领取、汇报、提交和验收同一类任务；不支持自动化的能力明确显示，不妨碍其他节点使用。
7. 断线、中枢重启或取消后，原执行可被核实；未确认停止的写入进程不会与新执行争用同一目录。
8. 重复采集、超过 200 条历史事件、任务编号重建和跨日执行均不会造成重复计量或错误拼接。

达到上述场景才算综合闭环完成；仅有节点列表、CLI 可启动或几张统计图不算完成。

## 建议交付顺序与范围边界

1. **节点与执行基础**：任务实例、节点能力与容量、执行批次、统一交付、可靠事件历史。
2. **CodeBuddy 国内站 CLI 闭环**：基于用户已手动验证可运行的命令行，验证中枢的受控派发、结果验收、取消与恢复对账；保留人工接入。
3. **任务与执行时间轴**：先覆盖已有任务阶段，再展示可验证的执行、等待与来源明细。
4. **多工具扩展与统计复盘**：逐个验收接入器，启用来源支持的会话、轮次、用量和自动选择能力。

本轮目标保持本机使用。云端多机集群、统一购买／共享各平台额度、接管任意已打开的桌面聊天、按投入量给人打分、默认采集完整提示词或模型内部推理，不纳入这两组需求的综合范围。费用预测和额外自动生成日报也暂不作为必要交付。

最新前提：用户随后确认 CodeBuddy 命令行已经手动测试，可以运行；据此不再将此前认证要求视为当前阻塞。WorkBuddy、ZCode 与 Trae 的记录仍以各自最近实测为准。CodeBuddy 可独立运行不等于 maw 自动派发、取消、恢复和观测已交付。

本清单对应的架构边界、状态模型与接口方案见 [综合架构规划](ARCHITECTURE_VNEXT.zh-CN.md)，该文档只做架构规划，不拆任务或启动实施。
